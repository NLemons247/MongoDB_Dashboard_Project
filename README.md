<H2>How do you write programs that are maintainable, readable, and adaptable? What were the advantages of working in this way? How else could you use the CRUD Python module in the future?</H2>

<P>There are a lot of different aspects that go into writing maintainable, readable, and adaptable/scaleable code. One of the easiest ways is to set your code up to be modular, by this I mean breaking your code down into smaller, self-contained modules or functions (like we did with the CRUD Python module). This allows me to add or change parameters with ease and without risking breaking another part of the setup. Clear naming conventions and consistent style are also important, using descriptive variable, function and class names is pivotal for readablility and being able to understand when you, or someone else, comes back to review or change your work. Documentation is also important, this can span anywhere from in-line comments to commit-comments, or README files to full blown user guides. Whatever you do, you need to make sure that your process is documented somewhere to explain your reasoning in some fashion. Testing is also crucial, without testing your code adequately, how do you even know that it will work? We did this, I believe in module 5, by testing to make sure that our AnimalShelter class worked in our Python module. Outside of the class, version control is also very important because it can allow you to create iteratively and also track changes, collaborate, and manage different versions of a project. This is invaluable when you want to create code that is up to production standards. Some possible future uses for the Python CRUD module that we were tasked with creating could include adapting it to other applications or new projects. We can also extend on what is already built and make it more complex for more advanced database features. The CRUD module I have created isn't that sophisticated and there are plenty of things that it still can't handle, but it is a good base to start out with if I need to create something similar in the future.</P>

<H2>How do you approach a problem as a computer scientist? Consider how you approached the database and dashboard requirements that Grazioso Salvare requested. <P>The first step to solving any problem is to understand the problem that needs to be fixed or taken care of. After this is done, you can move on to formulating a plan and then implementing that plan. After implementation comes testing, and depending on whether or not you are satisfied with the result you can either iterate through the previous steps again or you can start focusing on performance and efficiency of the solution. I don't think that I really approached the problems in this project much more differently than any other projects in the past, except maybe that every time I have to solve a problem for a project my process becomes a little more refined in what research I need to do and what method I decide to move forward with. We were already given the style and type of database software we were supposed to use so we really didn't need to brainstorm whether or not a SQL or NoSQL database framework was going to work better for the project. Other than that, there was a lot of trial and error, and flipping between the textbook, MongoDB documentation, and then trying out what I had found to make my dashboard work how I wanted it to. There were still a few hiccups that I didn't end up getting sorted out, which I considered to be in the efficiency/performance stage of my problem solving and this was with the pie-chart resizing depending on the amount of different breeds in the search query. But as I said, I felt this was more in the efficiency/performance category and wasn't as important as other aspects I decided to focus on instead./P>
